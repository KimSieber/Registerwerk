## 3. Fehler: geladene Dateien blieben lokal

**Befund (Kim, 25.11.2026):** Ein Lauf über 106 Dateien zeigte bei „Aus der Cloud laden“ einen Kreis statt eines Hakens, „0 geladen“, und stellte die Dateien danach nicht auf „nur online“ zurück.

**Ursache:** Welche Dateien geladen wurden, stand nur im Arbeitsspeicher des Laufs (`LadenErgebnis.geladene`). Nur diese Liste ging an „Wieder nur online“. Sie ging verloren, wenn

1. eine Datei erst nach dem Warten ankam (2 Minuten ohne neue Datei oder „Nicht warten, weiter“),
2. der Lauf nach dem Laden angehalten wurde,
3. ein Schritt nach dem Laden mit einem Fehler abbrach.

Der nächste Lauf fand die Dateien lokal vor, lud nichts und stellte nichts zurück. Der Kreis kam daher, dass ein Schritt ohne Dateien keine Meldung schickte. Ohne Meldung bekam er keinen Haken.

**Korrektur:**

- Tabelle `angefordert` (Datei, Gerät, Zeit). `ablauf::laden()` vermerkt jede Datei, bevor sie angefordert wird (`Register::angefordert_eintragen`).
- „Wieder nur online“ nimmt alle vermerkten Dateien dieses Geräts, die lokal liegen und keinen Schritt mehr offen haben (`ablauf::auszulagern`, `Register::angefordert_fertig`), auch aus früheren Läufen.
- Der Vermerk entfällt nach dem Zurückstellen, wenn die Datei schon wieder „nur online“ liegt (etwa von Hand zurückgestellt) und mit dem Eintrag im Register (`ON DELETE CASCADE`).
- Je Gerät, weil „lokal“ nur auf einem Gerät gilt. Ein anderes Gerät stellt nichts zurück.
- Bewusst lokal gehaltene Dateien tragen nie einen Vermerk und bleiben lokal.
- Jeder Schritt meldet zuerst seinen Beginn (`gesamt = 0`). Die Oberfläche zeigt für das Laden ohne Dateien „nichts zu laden“.

Die 106 Dateien des Befunds hat Kim von Hand zurückgestellt.

### Änderungen am Code für die Tests

- `ablauf::auslagern()` ruft `auslagern_mit()` mit dem Werkzeug als Angabe auf. Sonst hätte ein Test das echte `onlineonly` aufgerufen und Kims Dropbox angefasst.
- Gleiche Fehlermeldungen zusammengefasst: `dokumente::roh()` und `xml_fehler()`, `textebene::seite_fehler()`.
- `pdf::einbinden()` ohne kleine Fehlerfunktionen. Ein Fehler beim Laden von PDFium lässt sich im Test nicht auslösen, weil die Bibliothek nur einmal je Lauf geladen wird.

## 5. Grenze der Abdeckung

| Regel | Festlegung |
|---|---|
| Zeilen | mindestens 90 % je Datei |
| Funktionen | mindestens 90 % je Datei (Kim, statt nur in der Summe) |
| Ausnahmen | nur in `scripts/abdeckung-ausnahmen.json`: `datei`, `grund`, eigene Grenze für `zeilen`, `funktionen` oder beides, unter 90 %. Eine Grenze darf nur steigen |
| Neue Dateien | gelten ohne Ausnahme mit 90 % |
| Rot | eine Datei unter ihrer Grenze, eine Ausnahme für eine unbekannte Datei, ohne Grund oder ohne gültige Grenze |
| Hinweis, nicht rot | eine Ausnahme, die nicht mehr nötig ist |
| Geltung | nur `npm run pruefen` über den ganzen Workspace. Mit Filter oder einzelnem Paket wäre die Abdeckung unvollständig |

`npm run pruefen` legt zusätzlich `target/pruefen/abdeckung.json` ab (`cargo llvm-cov report --json`). Daraus lassen sich die nie aufgerufenen Funktionen einer Datei mit Zeilennummer ermitteln. Die Tabelle von llvm-cov zeigt nur Zahlen. Mehrere Ausprägungen einer generischen Funktion zählen wie llvm-cov als eine.

Code: `GRENZE` und `grenzePruefen()` in `scripts/auswertung.mjs`, Laden der Ausnahmen in `scripts/pruefen.mjs`.

## 6. Fehler: Excel 5 und 95 ohne Text

Der eigene Leser für Excel 5 und 95 (`biff.rs`) kam nur zum Zug, wenn calamine an der Datei mit einem Fehler scheiterte. Ein Test zeigte: calamine öffnet manche solche Mappe ohne Fehler, liefert aber keine Blätter. Die Datei hätte dann als gelesen mit 0 Seiten gegolten, ohne Text und ohne Meldung.

**Korrektur:** `altoffice::excel()` erkennt BIFF5 im Strom `Workbook` oder `Book` selbst und liest es vor calamine. Ab Excel 97 bleibt es bei calamine.

**Bestand:** Eine einmalige Umstellung, die betroffene Mappen (`.xls`/`.xlt`, fehlerfrei, 0 Seiten) zum Neulesen markiert, wurde gebaut, bei Kim ausgeführt und wieder entfernt. Sie fand keine betroffene Mappe. Im Register steht davon noch der Vermerk `excel5_eigen` in `merkmal`. Er schadet nicht, das Programm fragt ihn nicht ab.

## 7. Vorgehen

1. Übergabe und Konzept gelesen, Version auf 0.1.2.
2. Fehler beim Laden aus dem Screenshot und dem Code hergeleitet, Korrektur mit Tests, bei Kim geprüft.
3. Offene Punkte der Übergabe geklärt: Test-PDF ins Repo, fehlende Bibliotheken machen die Tests rot.
4. Tests in der Reihenfolge der Übergabe ergänzt: echte PDF, Vorschau, Leser alter Formate, Fehlerzweige. Nach jedem Schritt `npm run pruefen` bei Kim. Auf Kims Mac ist von Claude aus kein cargo erreichbar, die Tests entstehen ohne Compiler. Fehler beim Übersetzen und falsche Erwartungen (PDFium rundet 1448,5 px auf 1449) wurden nach dem Protokoll behoben.
5. Grenze für Zeilen je Datei eingeschaltet, danach auf Kims Wunsch auch für Funktionen je Datei.
6. Einmalige Umstellung für Excel 5 gebaut und auf Kims Wunsch zurückgenommen (Abschnitt 6).

## 8. Entscheidungen

| Thema | Entscheidung | Grund |
|---|---|---|
| Geladene Dateien | Vermerk im Register je Gerät, Zurückstellen auch aus früheren Läufen | die Liste im Arbeitsspeicher ging bei Abbruch und spätem Eintreffen verloren |
| Schritt ohne Dateien | Haken, beim Laden „nichts zu laden“ | ein Kreis sah aus, als sei der Schritt nicht gelaufen (Kim) |
| Test-PDF | selbst erzeugt, im Repo, mit Skript | Kim |
| Fehlende Bibliotheken | Tests rot | Kim. Still übersprungene Tests haben `pdf.rs` bei 0 % verdeckt |
| Grenze | 90 % der Zeilen und Funktionen je Datei | Kim. Ursprünglich Funktionen nur in der Summe, der Weg zu je Datei war aber kurz |
| Ausnahmen | Liste mit Grund, Grenze nur steigend, leer | Kim |
| Excel 5 | eigener Leser vor calamine | calamine lieferte ohne Fehler keine Blätter |
| Umstellung für Excel 5 | zurückgenommen | fand keine Datei, Kim wollte keine einmaligen Läufe ohne Bedarf |
| Punkte aus v0.1.1 | Prüfung in der Anwendung in v0.1.3, mit festgelegtem Testablauf | Kim |
| Version | 0.1.2 | Kim |

## 9. Bekannte Einschränkungen und Annahmen

- **Nicht testbar ohne echte Cloud:** das Anfordern über die Dateikoordination (`registerwerk_macos::anfordern`) und `onlineonly` selbst. Getestet ist alles darum herum, mit Ersatz.
- **Ein Fehler beim Laden von PDFium** bleibt ungetestet (einmal je Lauf geladen).
- **Prozentwerte schwanken** leicht mit der Rundung von PDFium und Tesseract. Tests mit Bildmaßen lassen ein Pixel Spielraum.
- **Annahme:** Die Abdeckung von `registerwerk-macos` (5 Funktionen) bleibt über 90 %, solange jede Funktion einen Test hat. Eine neue Funktion ohne Test macht sie sofort rot.
