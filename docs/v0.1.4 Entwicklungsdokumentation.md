## 4. Register absichern

### Unverschlüsselte Dateien bei hinterlegtem Schlüssel (S7-a1ec7313, A5-e8e00dc7)

**Befund:** Eine unverschlüsselte Datei im Register-Ordner wurde auch dann geöffnet und beschrieben, wenn auf dem Gerät ein Schlüssel hinterlegt war. Eine zurückgespielte ältere Fassung, eine Konfliktkopie oder eine ausgetauschte Datei hätte die Verschlüsselung still ausgeschaltet.

**Regel** (Kim): Ist für den Register-Ordner ein Schlüssel hinterlegt, öffnet `verbinden()` keine unverschlüsselte Datei mehr, weder die Index-Datenbank noch eine Scheibe. Fehler `Unverschluesselt`. Ohne Schlüssel bleibt alles wie bisher. Ein neuer Merker ist nicht nötig, das Register wird nicht angefasst.

**Oberfläche:** Statt der Suche erscheint der Kasten „Register nicht vollständig verschlüsselt“ mit Erklärung, Liste der unverschlüsselten Dateien und dem Schritt „Bestätigen und verschlüsseln“. Nach einem vollständigen Lauf lädt die Anwendung neu. Auch nach „Schlüssel speichern“ bei einem unverschlüsselten Register lädt sie neu und zeigt diese Sperre.

**Folge:** Eine angehaltene Umstellung sperrt das Register, bis sie fertig ist. Bis v0.1.3 ließ sich dazwischen weiter suchen.

### Kein angehängtes SQL (S2-5ef6f419, Gate G2)

**Befund:** Die Probe beim Start legt Kopien von vier Tabellen im Arbeitsspeicher an und nahm dafür die gespeicherte Definition aus der Datei. Sie lief als Stapel, angehängtes SQL wäre mitgelaufen.

**Korrektur:** Die Definition muss mit `CREATE TABLE` beginnen und genau eine Anweisung sein (`mehrere_anweisungen`). Ein Semikolon in Zeichenketten, Bezeichnern und Kommentaren zählt nicht, die Definition von `datei` enthält eins im Kommentar. Sonst bricht die Probe mit Fehler ab.

### Pfadprüfung zentral (S2-92264674, A5-cb5be2c7)

`Konfiguration::ort` liefert keinen Ort mehr für Pfade mit `..`, mit absolutem Rest oder mit Laufwerk. Die drei verstreuten Prüfungen in `dateibaum.rs` und `main.rs` sind entfallen. Pfade aus dem Register führen so nicht aus dem Ast hinaus, auch nicht beim Öffnen des Originals.

### Ablage der Schlüssel (S9-0a67a1af)

`kennung()` löste den Ordner entgegen seinem Kommentar über das Dateisystem auf. Ein Schlüssel, der vor dem Anlegen des Ordners hinterlegt wurde, galt danach unter einem anderen Pfad, wenn eine Verknüpfung im Pfad lag, und ein neues Register wäre unverschlüsselt entstanden. Jetzt nur lexikalisch.

### Neue Tests

- `probe_fuehrt_kein_angehaengtes_sql_aus`: stellt das Finding nach, das angehängte SQL läuft nicht.
- `erkennt_mehrere_anweisungen`
- `schluessel_fuer_noch_nicht_angelegten_ordner`: mit Verknüpfung im Pfad.
- Ergänzt: Sperre bei unverschlüsseltem Register in den Tests der Umstellung und der Scheiben, Pfade mit `..` in den Tests der Konfiguration.

### Prüfung in der Anwendung

Am echten Register: Start, Suche, Datenbank-Symbol und „Erneut prüfen“ wie bisher. An einem eigenen Test-Register mit Testschlüssel: Schlüssel speichern → Sperre → verschlüsseln → Suche. Danach Testschlüssel entfernt und Test-Register gelöscht. Bestanden.

## 5. PDFium 8179 (D1-ed42aea1, D4-cddad328)

- Build 8179 statt 8125. Chrome hat im November 2026 eine Lücke in PDFium geschlossen, die 8125 sehr wahrscheinlich fehlt.
- `tools/pdfium_holen.sh` prüft die SHA-256-Prüfsumme jedes Archivs und entpackt sonst nicht.
- Das Feature von pdfium-render bleibt `pdfium_8125`, das neueste, das pdfium-render kennt. Es darf älter sein als der Build. pdfium-render 0.9.6.
- **Fehler beim ersten Lauf:** Das Skript überschrieb die Bibliothek an Ort und Stelle. macOS beendet dann jeden Prozess, der sie lädt (SIGKILL). Jetzt wird sie unter einem Hilfsnamen abgelegt und umbenannt.
- Vergleich mit `pdf_pruefen --still` vor und nach dem Wechsel an 14 PDFs: Seiten, Fehler und Text unverändert.
- Das Lese-Verfahren hat keine neue Version, der Bestand wird nicht neu gelesen.

## 8. Entscheidungen

| Thema | Entscheidung | Grund |
|---|---|---|
| Ablage des Review-Berichts | `docs/intern/reviews/`, nicht im Repo | beschreibt Schwachstellen, das Repo ist öffentlich (Kim) |
| Agent CodeReview | keine Änderung durch Claude, nur Vorschläge | Kim pflegt den Agenten selbst |
| Unverschlüsselte Datei bei hinterlegtem Schlüssel | gesperrt, ohne neuen Merker, Umstellung als Ausweg | schützt vor stillem Weiterschreiben ohne Verschlüsselung, ändert das Register nicht (Kim) |
| Definition der Hilfstabellen | aus der Datei, aber nur als genau eine Anweisung | eine feste Kopie im Programm müsste jede Änderung des Schemas nachziehen |
| Umfang v0.1.4 | Paket 1, PDFium, HEIC, kleine Punkte | geringes Risiko für den produktiven Bestand (Kim) |
| PDFium-Update | in v0.1.4 vorgezogen | Lücke wahrscheinlich, kleiner Aufwand, kein Neulesen (Kim) |
| SQLCipher-Update | eigene Version, erst an einer Kopie | höchstes Risiko für das produktive Register |
| Konventionen des Reviews | deutsche Namen und Dateiköpfe bleiben | Projektentscheidung, die Instruktion des Agenten wird angepasst |

## 9. Bekannte Einschränkungen und Annahmen

- **Gate G2** gilt mit dieser Version als behoben. Ein neuer Lauf des Reviews bestätigt das erst.
- **Oberfläche ohne Tests.** Die Sperre ist von Hand in der Anwendung geprüft.
- **Gefunden beim Test, offen:** Die aufgeklappte Gruppe „Sonstige“ im Filter der Suche verdrängt die Treffer und scrollt nicht. Dort stehen auch Endungen von Quelltext und Programmen (PHP, JS, EXE), vermutlich aus Ordnern der Stufe „Nur Namen“. Beides in v0.1.5.
- **Annahme:** Der Cloud-Ordner bleibt die einzige Quelle für Register-Dateien. `regeln.toml` und `textebene.log` liegen weiter unverschlüsselt daneben.
